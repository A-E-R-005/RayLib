Currently, the soldier always faces the same direction (likely right, since sprites are drawn that way), even when moving left. This breaks the illusion of movement.

The fix is to flip the texture horizontally when the player is moving left.

1. The Key to Flipping: `sourceRec.width`
	In raylib, flipping a sprite is achieved by simply setting the width component of the `sourceRec` to a negative value.
		- To Draw Normally (Facing Right): `sourceRec.width = +frameWidth`
		- To Flip (Facing Left): `sourceRec.width = -frameWidth`
	When the width is negative, raylib automatically draws the texture horizontally flipped, starting the drawing from the correct left-hand edge of the frame.

2. Implementation Logic
	The logic for flipping must be determined in the Update phase, after input is processed, and applied before the Draw phase.
	A. Determine Direction
		We look at the player's horizontal movement (`playerDirection.x`):
		- If `playerDirection.x > 0`: Moving Right -> Normal
		- If `playerDirection.x < 0`: Moving Left -> Flip
		- If `playerDirection.x == 0`: No horizontal movement -> Keep the last direction (e.g., if they were moving right, they should still face right while idling).
	B. Applying the Flip to `sourceRec`
		Since your `SheetAnim::Alogic()` function calculates the `sourceRect`, we need to expose the ability to flip the width in that structure.

3. Required Structural Adjustments
	We need to modify the `SheetAnim` logic to handle the `playerDirection.x` input.
	A. `sheetanimation.h` (Add Direction Input)
		The animation logic needs to know the player's direction to decide whether to flip
	B. `sheetanimation.cpp` (Implement Flipping Logic)
		We implement the core flipping logic
	C. `main.cpp` (Passing Direction)
		You now need to pass the `playerDirection.x` value to the active animation instance before drawing

    // ... (Existing timer/frame advance logic remains the same) ...

    // 1. Reset sourceRec width to normal
    sourceRect.width = frameWidth; 

    // 2. Check for movement left (directionX < 0)
    if (directionX < 0) {
        // Apply the flip: make width negative
        sourceRect.width = -frameWidth; 
    }
    
    // If directionX > 0, width remains positive (normal)
    // If directionX == 0, we keep the previous width from the last frame
    
    // Calculate X offset for frame index (remains the same)
    sourceRect.x = frameIndex * frameWidth; 
    sourceRect.y = 0.0f;
    sourceRect.height = frameHeight;
}
